## 每个功能文件应记录
功能 ID、负责人、确认的需求来源、实现源码入口、验证状态及最近证据。
沿用 Pstack 的四个章节：
- `Sub-features`：范围、前置条件、可观察预期及副作用；区分已确认需求与待确认问题。
- `How to get to it (user POV)`：用户入口、页面/命令路径、登录与数据要求。
- `Driving it with <实际工具>`：真实可执行命令或稳定选择器、逐步动作与逐步断言；有多个入口时分别记录覆盖情况。
- `Gotchas`：权限、外部环境、数据缺口、清理方式和限制。
